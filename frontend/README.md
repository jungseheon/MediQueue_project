# 환자용 프론트엔드

흑백 카드, PC 사이드바, 모바일 하단 메뉴로 구성한 환자용 화면입니다. 빌드 없이 실행하며, 의사 목록·환자 정보·예약·대기 정보는 모두 백엔드 API(`http://<접속 호스트>:3000`)에서 읽고 씁니다. Node.js 20 이상을 사용하세요. 병원용 화면은 `hospital/` 폴더에 있습니다([hospital/README.md](hospital/README.md)).

## 실행

1. 저장소 최상위 README의 실행 방법대로 DB와 백엔드(`npm run dev`, 포트 3000)를 실행합니다. 시연에는 `dump.sql` 샘플 데이터가 필요합니다.
2. 다른 터미널에서 `npm run dev:patient`를 실행한 뒤 http://localhost:5173 에 접속합니다. npm이 없는 환경에서는 `node frontend/server.mjs`로 실행할 수 있습니다. 종료는 Ctrl+C입니다. 포트 변경은 PowerShell에서 `$env:PATIENT_PORT=5174` 설정 후 실행합니다.

백엔드가 꺼져 있으면 화면에 연결 오류와 "다시 시도" 버튼이 표시됩니다.

## 사용하는 API

| 화면 동작 | API |
| --- | --- |
| 병원·담당의 목록 | `GET /api/doctors` |
| 환자 이름 표시 | `GET /api/patients/:id` |
| 내 예약 목록 | `GET /api/appointments?patientId=` |
| 예약 가능 시간(다른 환자 예약 확인) | `GET /api/appointments?doctorId=&status=booked` |
| 예약·변경·취소 | `POST /api/appointments`, `PATCH /api/appointments/:id`, `DELETE /api/appointments/:id` |
| 대기 순번·앞 인원·예상 진료 시각·호출 여부 | `GET /api/appointments/:id/wait` (내 예약 정보만 받음) |

## 시연용 고정값 (백엔드 기능이 생기면 교체)

- 환자: 로그인 기능이 없어 `api.mjs`의 `PATIENT_ID = '4'`(dump.sql의 양윤서)로 고정합니다. 이름은 환자 API에서 받아 홈에 표시하며, 이 환자가 DB에 없으면 오류 안내가 나옵니다.
- 병원: 백엔드에 병원 테이블이 없어 `model.mjs`의 `clinics`에 병원 이름·지역과 의사 ID만 적어 둡니다(온유·마음봄 정신건강의학과 = 13, 23번). 의사 이름과 진료과는 의사 목록 API에서 받습니다. `clinics`에 연결되지 않은 의사는 진료과별 "○○ 협력 병원"으로 묶어 보여 주므로, DB의 모든 의사에게 예약·변경할 수 있습니다. `clinics`의 의사가 DB에 없으면 그 병원은 목록에서 숨깁니다.
- 진료 유형(초진/재진): 예약 API에 해당 필드가 없어 선택 항목을 뺐습니다. 서버가 진료 기록으로 판단합니다.
- 예약 시간대: 13:30~15:30, 30분 간격입니다.

## 시연 순서

1. 홈에서 오늘의 예약과 다음 예약 확인
2. 병원 검색·예약에서 `마포` 검색 후 마음봄 선택 (진료과나 의사 이름으로도 검색 가능. 예: `소아`)
3. 담당의, 날짜, 시간 선택 (다른 환자가 예약한 시간은 "마감", 오늘 지난 시간은 "지남")
4. 예약 내용 확인 → 예약 확정 → 내 예약에서 결과 확인
5. 예약 변경으로 시간 변경 및 확정, 예약 취소 후 확정 → 지난 진료·취소 탭에서 확인
6. 병원용 화면이나 API로 오늘 예약을 체크인한 뒤 새로고침 → 대기 순번, 내 앞 대기 인원, 예상 진료 시각, 예상 지연 표시 (체크인 후에는 변경·취소 버튼이 사라짐)
7. 병원용 대시보드에서 호출·부재·진료 시작 → 30초 안에(또는 새로고침 시) 호출 안내, 순서 미뤄짐 안내, 진료 중 표시
8. 브라우저 폭을 390px로 줄여 하단 메뉴와 세로 레이아웃 확인

## 대기 정보 자동 갱신

- 홈과 내 예약 화면은 30초마다 의사 목록·내 예약·대기 정보를 다시 불러옵니다. 로딩 표시 없이 바뀌며, 실패하면 기존 화면을 그대로 둡니다.
- 병원 검색·예약 화면에 있거나 확인 창이 열려 있거나 요청 처리 중이거나 브라우저 탭이 가려져 있으면 갱신하지 않습니다(입력 중인 내용 보호).
- 홈의 '최근 알림'은 호출 → 진료 임박(내 앞 0명) → 지연(의사별 지연 알림 기준 이상) 순으로 하나를 보여 주며, 알림 설정 스위치를 끄면 해당 알림은 표시하지 않습니다.

## 로딩·오류 처리

- 의사 목록·환자 정보·예약 목록과 예약 가능 시간을 불러오는 동안 로딩 표시가 나오며, 실패하면 오류 안내와 "다시 시도" 버튼을 보여 줍니다. 병원 검색 화면도 의사 목록을 받기 전에는 로딩·오류 안내를 보여 줍니다.
- 대기 정보는 예약별로 따로 불러오므로 한 건이 실패해도 나머지 예약은 표시되고, 실패한 예약은 예상 시각을 "계산 중"으로 표시합니다.
- 예약·변경·취소 요청 중에는 버튼이 "처리 중…"으로 바뀌고 비활성화되어 중복 요청을 막습니다. 요청 중에는 Escape로 창을 닫을 수 없습니다.
- 요청이 8초 안에 끝나지 않거나 서버에 연결할 수 없으면 안내 문구를 표시합니다.
- 서버 응답 400·404·409는 각각 입력 확인, 예약 없음, 체크인·취소된 예약 안내로 바꿔 보여 주고, 404·409이면 예약 목록을 다시 불러옵니다.

## 파일

- `index.html`: 공통 메뉴 및 접근성 기본 구조
- `app.js`: 화면 렌더링, 로딩·오류 상태, 검색·예약·변경·취소 이벤트
- `api.mjs`: 백엔드 API 호출과 오류 메시지 (요청별 안내 문구 지정 가능)
- `model.mjs`: 의사 목록 → 병원 목록 구성, 검색, 서버 데이터·대기 정보 변환, 예약 검증, 날짜 계산
- `style.css`: PC·태블릿·모바일 반응형
- `server.mjs`: 로컬 정적 파일 서버

알림 설정만 브라우저 localStorage의 `mediqueue-patient-settings`에 저장합니다(실제 알림 전송은 없음).

## 검증

`npm run test:patient`로 의사 목록 → 병원 목록 구성, 병원·진료과·의사 검색, 서버 데이터 변환(시간대, 취소·완료·노쇼 상태), 대기 정보 변환과 체크인 이후 상태 변화, 마감·지난 시간, 변경 시 자기 예약 제외, 내 예약 중복, 과거 날짜와 입력 검증을 확인합니다. 백엔드 없이 실행됩니다.
